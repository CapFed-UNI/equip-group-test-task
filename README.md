# Каталог интернет-магазина

Laravel-каталог групп и товаров с сортировкой, пагинацией, карточкой товара и хлебными крошками. Стек: PHP 8.4, Laravel 13, MySQL 8, Bootstrap 5.

## Запуск

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Сайт: [http://localhost:8080](http://localhost:8080)

Первый запуск ставит зависимости Composer, выполняет миграции и наполняет БД. Повторный `db:seed` не дублирует данные, если группы уже есть. Если Composer не скачает пакеты из-за лимита GitHub, просто повторите `docker compose up` — кэш зависимостей сохраняется.

Остановить:

```bash
docker compose down
```

### Наполнение БД

По умолчанию данные генерируются через Faker (`CATALOG_SEED=faker`).

Чтобы загрузить демо-данные из [test.sql](test.sql) (удобно сверять со скриншотами ТЗ):

```bash
CATALOG_SEED=dump docker compose up --build
```

На Windows PowerShell:

```powershell
$env:CATALOG_SEED='dump'; docker compose up --build
```

Либо после старта:

```bash
docker compose exec app php artisan migrate:fresh --seed --force
```

(для дампа предварительно выставьте `CATALOG_SEED=dump` в `.env`)

### Тесты

```bash
docker compose exec app php artisan test
```

Покрыты дерево групп и счётчики, сортировка/пагинация, AJAX-фрагмент, карточка товара и импорт `test.sql`.

## Архитектура

```text
HTTP  → CatalogController
          → CatalogService
              → GroupTreeService     дерево групп, счётчики, сайдбар, крошки
              → ProductRepository    выборка товаров с ценой, сортировка, пагинация
```

- Контроллер тонкий: список, группа, карточка товара.
- Дерево групп собирается в памяти после двух SQL-запросов: все группы и `COUNT(*) GROUP BY id_group`. Количество товаров в группе — сумма по ней и всем потомкам (без N+1 и без рекурсивного SQL на каждый узел).
- Товары выбираются одним `JOIN prices` с `WHERE id_group IN (...)` и `LIMIT/OFFSET`.
- `GroupTreeService` зарегистрирован как singleton на запрос, чтобы не перечитывать дерево.

Маршруты:

| URL | Назначение |
| --- | --- |
| `/` | Корневые группы и все товары |
| `/group/{id}` | Подгруппы и товары выбранной ветки |
| `/product/{id}` | Карточка товара |

Query-параметры: `sort` (`price_asc`, `price_desc`, `name_asc`, `name_desc`), `page`, `per_page` (`6`, `12`, `18`).

## Принятые решения

1. **Схема из `test.sql`, данные — Faker.** Дамп в ТЗ описывает структуру таблиц `groups`, `products`, `prices`. Основной сидер (`CatalogFakerSeeder`) строит похожее дерево категорий и наполняет листья товарами и ценами через Faker. Импорт дампа оставлен в `CatalogDumpSeeder` и включается через `CATALOG_SEED=dump`.
2. **`id_parent = 0` без внешнего ключа.** В дампе корень кодируется нулём, а не `NULL`. FK на родителя не ставится, чтобы не требовать строки с `id = 0`.
3. **Сортировка по умолчанию — по `id`.** На скриншотах ТЗ товары идут в порядке идентификаторов.
4. **AJAX как прогрессивное улучшение.** Сортировка, `per_page` и пагинация обновляют блок `#catalog-listing` без перезагрузки. URL меняется через `history.pushState`, поэтому ссылку можно скопировать. Без JavaScript те же ссылки работают обычной перезагрузкой.
5. **Сайдбар.** На главной видны только группы первого уровня. Внутри группы раскрыт путь до текущей: предки зелёным, текущая группа выделена, соседи на каждом уровне пути видны.
6. **Одна цена на товар.** В дампе связь 1:1; уникальный индекс на `prices.id_product`.
7. **Таблица `groups`.** Имя зарезервировано в SQL, в модели задано явно, идентификаторы в запросах берутся в кавычки драйвером Laravel.

## Задача: Разработка каталога интернет-магазина

> **Время выполнения**: Выделите на задание от 5 до 24 рабочих часов. Если не успеваете выполнить все пункты, вышлите, что успели. Максимальный срок — 5 дней.

### Входные данные
Вам нужно создать каталог товаров с возможностью сортировки и пагинации на основе приложенной базы данных. Все данные о товарах, группах и ценах находятся в дампе базы [test.sql](test.sql), который содержит три таблицы:

1. **groups** — таблица групп товаров:
    - `id` — идентификатор группы;
    - `id_parent` — идентификатор «родительской» группы;
    - `name` — название группы.
2. **products** — таблица товаров:
    - `id` — идентификатор товара;
    - `id_group` — идентификатор группы товаров;
    - `name` — название товара.
3. **prices** — таблица цен:
    - `id` — идентификатор записи;
    - `id_product` — идентификатор товара;
    - `price` — цена товара.

### Основная задача
1. На главной странице должен выводиться список групп товаров (название и URL) первого уровня (группы, у которых `id_parent=0`) и список всех товаров с возможностью сортировки и пагинации:
     - Сортировка по цене (по возрастанию и убыванию);
     - Сортировка по названию (по возрастанию и убыванию).
2. Возле названия каждой группы должно быть указано общее количество товаров в этой группе и всех её подгруппах;
3. При выборе группы товаров отображаются все подгруппы и товары в выбранной группе и подгруппах. Сортировка и пагинация должны работать только в пределах выбранной группы;
4. Каждый товар должен отображаться с названием и ценой. При выборе товара должна открываться карточка товара с информацией:
     - Название товара;
     - Цена;
     - Хлебные крошки (включая все родительские группы товара).
5. Внешний вид с использованием Bootstrap, поддержка адаптивности.
